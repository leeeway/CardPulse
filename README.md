# CardPulse

**在浏览器中整理信用卡账单，核对交易并估算返现。**

**简体中文** · [繁體中文](README.zh-TW.md) · [English](README.en.md)

CardPulse 是一个本地处理的信用卡 PDF 账单分析工具。导入受支持的结单后，可以按商户、币种和收支筛选交易，检查账单结欠是否一致，并查看基于内置规则计算的返现估算。需要保留记录时，可使用主密码加密保存到当前浏览器。

适合希望集中整理多个月份账单，同时让交易明细留在自己设备上的用户。目前主要面向 **HSBC Pulse 双币信用卡**；支持范围见下表。

[快速开始](#快速开始) · [使用流程](#使用流程) · [支持范围](#支持范围) · [隐私与数据](#隐私与数据) · [开发与贡献](#开发与贡献)

## 能做什么

- **整理交易**：批量导入 PDF，查看交易日期、商户、币种、金额及识别到的支付渠道；支持搜索、筛选和 CSV 导出。
- **检查账单**：按币种核对“上期结欠 + 支出 − 入账 = 本期结欠”，显示对账结果及差额。
- **估算返现**：按内置 Pulse 规则计算基础及额外奖赏，显示年度、半年度消费额度的使用情况；退款扣回奖赏，但不释放已占用额度。
- **加密保存**：将交易与结单摘要加密保存在当前浏览器，刷新后输入主密码恢复；也可手动锁定或清空。
- **减少误操作**：按 PDF 文件内容识别重复导入，提示解析异常和未保存的修改。

## 快速开始

需要 Node.js 和 npm，建议使用 **Node.js 22.13 或更高版本**。浏览器须支持 Web Crypto、Web Worker 和 IndexedDB；请通过本地开发地址或 HTTPS 访问应用。

```bash
git clone https://github.com/leeeway/CardPulse.git
cd CardPulse
npm ci
npm run dev
```

打开终端显示的本地地址，通常为 `http://localhost:5173`。首次使用可点击 **“查看示例数据”**，无需准备真实账单。

## 使用流程

1. **导入账单**：点击上传区域或拖入一个或多个 PDF。加密文件会提示输入 PDF 密码；取消则跳过该文件，继续处理其余文件。
2. **检查识别结果**：核对交易和支付渠道，查看每份结单的警告及对账状态。无法确认的记录应与原始 PDF 人工比对。
3. **查看返现估算**：看板汇总本年度截至当天的合资格记录。港币返现按公开参考汇率折算；汇率不可用时，相关人民币合计显示为未知。
4. **保存记录**：点击 **“保存到加密库”**，首次设置主密码，后续使用现有密码保存更新。**导入后不会自动保存。**
5. **恢复或导出**：再次打开应用后解锁本地库；CSV 导出仅包含当前筛选结果。

对账状态说明：

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 对账一致 | 已识别的期初、期末结欠与交易净额一致 | 仍需抽查分类和支付渠道 |
| 对账不符 | 计算出的结欠与结单结欠存在差额 | 检查遗漏交易、金额及结欠识别结果 |
| 未验证 | 缺少可识别的期初或期末结欠 | 对照原始 PDF 人工核对 |

对账一致仅表示金额平衡，不代表交易分类、渠道或返现资格已获银行确认。

## 支持范围

| 项目 | 当前支持情况 |
| --- | --- |
| HSBC Pulse | 在受支持结单布局下解析 CNY / HKD 交易，并按内置规则估算返现 |
| HSBC Red | 支持卡种与渠道识别、交易查阅和导出；尚未接入返现核算，不计入 Pulse 看板 |
| 文字型 PDF | 支持英文 `POST DATE` / `TRANS DATE` 表头、英文月份和固定相对列位置；表头上方须能唯一识别币种 |
| 扫描件 / 图片型 PDF | 暂不支持，尚未接入 OCR |
| 加密 PDF | 支持本地输入密码及错误后重试 |
| 导入限制 | 每个文件最多 25 MB、200 页 |
| 文档与界面语言 | 文档提供简体中文、繁体中文和英文；当前应用界面以简体中文为主 |

**返现规则是估算模型。** 当前未自动核验银行最新条款、活动登记、商户资格及个人权益条件。具体规则见 [Pulse 配置](src/core/rules/hsbc_pulse.js) 与[核算引擎](src/core/rewards.js)，最终以银行实际入账为准。

文件去重依据 PDF 原始字节内容。改名后的同一文件可识别为重复；内容不同但交易重叠的结单仍需人工排重。旧版保险库没有文件指纹和结单摘要，读取后重新导入时也需检查重复。

解析兼容性已通过合成数据验证，仍需要更多脱敏真实结单样本覆盖不同版式。遇到未支持格式时，请先核查解析结果。

## 隐私与数据

- **账单在本地处理**：应用没有接收账单的业务后端，PDF 解析和返现计算在浏览器内完成。
- **保存时加密**：使用 Web Crypto 的 PBKDF2（SHA-256，100,000 次迭代）派生密钥，再以 AES-256-GCM 加密，密文存放在 IndexedDB。主密码不会上传或持久化保存。
- **解锁后可查看明文**：交易在解锁期间存在于应用内存中。手动锁定会清除当前交易及结单状态，下次解锁恢复最后保存的版本。
- **存在公开汇率请求**：应用会请求 [Frankfurter](https://api.frankfurter.dev/v2/rate/HKD/CNY) 的 HKD/CNY 参考汇率，不发送账单内容，并设置 `credentials: 'omit'` 和 `referrerPolicy: 'no-referrer'`。这不代表整个应用完全不联网。
- **本地库依赖当前浏览器与站点地址**：切换设备、浏览器或访问地址不会自动同步数据。忘记主密码无法找回；清除站点数据也可能删除保险库。
- **CSV 是明文文件**：导出会转义可能触发电子表格公式的单元格，但交易内容仍可直接读取，请妥善保管。

“清空数据”会在确认后删除当前交易及本地保险库。“锁定保险库”遇到未保存修改时会提示是否丢弃，已保存记录保留。

## 开发与贡献

项目使用 React、Vite 和 PDF.js，无业务后端。

```bash
npm test          # Node.js 原生测试套件
npm run build     # 构建静态文件至 dist/
npm run preview   # 在本地预览构建结果
```

静态资源可部署到支持 HTTPS 的静态托管平台。部署到子路径时需配置 Vite 的 `base`；例如 GitHub 项目站点可使用 `npm run build -- --base=/CardPulse/`。

仓库提供 [GitHub Actions CI 模板](docs/ci.yml)，涵盖 Node.js 22/24 的测试与构建，目前尚未启用。具备相应仓库和工作流权限后，可将模板放入 `.github/workflows/ci.yml`。

主要模块：

| 路径 | 职责 |
| --- | --- |
| [`src/App.jsx`](src/App.jsx) | 导入、筛选、看板与保险库交互 |
| [`src/core/pdf.js`](src/core/pdf.js)、[`statement.js`](src/core/statement.js) | PDF 文本提取、坐标解析与结单摘要 |
| [`src/core/reconciliation.js`](src/core/reconciliation.js) | 金额转换与结欠校验 |
| [`src/core/rewards.js`](src/core/rewards.js)、[`rules/`](src/core/rules/) | 返现估算及卡种规则 |
| [`src/core/crypto.js`](src/core/crypto.js)、[`storage.js`](src/core/storage.js) | 加密与 IndexedDB 持久化 |
| [`tests/`](tests/) | 解析、精度、返现、存储及导出回归测试 |

欢迎通过 [Issues](https://github.com/leeeway/CardPulse/issues) 报告问题或提交改进。解析问题请提供银行与卡种、预期结果和已脱敏的版式示例；请勿公开真实卡号、姓名、交易明细或 PDF 密码。

修改功能、支持范围或使用流程时，请同步更新三个语言版本，保持章节顺序和功能状态一致。新增卡种或解析规则时，请附上脱敏或合成回归用例。
