# CardPulse

**在浏览器中整理信用卡账单，核对交易并估算返现。**

**简体中文** · [繁體中文](README.zh-TW.md) · [English](README.en.md)

CardPulse 是一个本地处理的信用卡 PDF 账单分析工具。导入受支持的结单后，可以按商户、币种和收支筛选交易，检查账单结欠是否一致，并查看基于内置规则计算的返现估算。需要保留记录时，可使用主密码加密保存到本地保险库。

适合希望集中整理多个月份账单，同时让交易明细留在自己设备上的用户。当前提供 HSBC、中银香港、信银国际、恒生、渣打、花旗、星展及其他银行工作区。HSBC 提供指定 PDF 布局解析；所有银行均可通过标准 CSV 整理交易及配置自定义活动。

[桌面下载](#桌面版下载与安装) · [快速开始](#快速开始) · [使用流程](#使用流程) · [支持范围](#支持范围) · [隐私与数据](#隐私与数据) · [开发与贡献](#开发与贡献)

## 能做什么

- **整理交易**：批量导入 PDF / 标准 CSV，查看交易日期、商户、币种、金额及识别到的支付渠道；支持搜索、筛选和 CSV 导出。
- **检查账单**：按币种核对“上期结欠 + 支出 − 入账 = 本期结欠”，显示对账结果及差额。
- **估算返现**：按内置 Pulse 规则计算基础及额外奖赏，显示年度、半年度消费额度的使用情况；退款扣回奖赏，但不释放已占用额度。
- **加密保存**：将交易、结单摘要与活动配置加密保存在当前浏览器或桌面应用数据目录，刷新后输入主密码恢复；也可手动锁定或清空。
- **减少误操作**：按 PDF 文件内容识别重复导入，提示解析异常和未保存的修改。

## 桌面版下载与安装

从 [GitHub Releases](https://github.com/leeeway/CardPulse/releases) 下载 `v0.2.0-beta.3` 桌面预览版。安装后即可使用，无需 Node.js、浏览器服务、账号或业务服务器。

| 系统 | 下载文件 | 安装方式 |
| --- | --- | --- |
| macOS 13+ · Apple 芯片 | `CardPulse-0.2.0-beta.3-mac-arm64.dmg` | 打开 DMG，将 CardPulse 拖到“应用程序” |
| macOS 13+ · Intel | `CardPulse-0.2.0-beta.3-mac-x64.dmg` | 打开 DMG，将 CardPulse 拖到“应用程序” |
| Windows 10 / 11 · x64 | `CardPulse-0.2.0-beta.3-win-x64.exe` | 运行安装向导，可为当前用户选择安装目录 |

Mac 同时提供 ZIP 包。此预览版的 Mac 包仅有本地 ad-hoc 签名，未使用 Apple Developer ID 签名或公证；Windows 包没有 Authenticode 发布者签名。系统可能拦截首次启动。确认来源及 SHA-256 后，可按 macOS“系统设置 → 隐私与安全性 → 仍要打开”或 Windows SmartScreen 的提示自行决定是否运行。请勿关闭系统全局安全保护。

Release 提供 `SHA256SUMS.txt`。将其与下载包放在同一目录，在 macOS 可运行 `shasum -a 256 -c SHA256SUMS.txt` 校验已下载文件；未下载的文件会报告缺失，可忽略其缺失提示。在 Windows PowerShell 可运行 `Get-FileHash .\CardPulse-0.2.0-beta.3-win-x64.exe -Algorithm SHA256` 并与清单比对。

这是桌面测试版。Mac 打包应用会进行启动、解析与持久化测试；Windows 安装包由 macOS 交叉构建，尚未经过原生 Windows 运行验收。问题可通过 Issues 反馈。卸载前建议先导出加密备份。

桌面数据保存在当前系统用户的应用数据目录：macOS 为 `~/Library/Application Support/CardPulse/vault.cardpulse`，Windows 为 `%APPDATA%/CardPulse/vault.cardpulse`。应用更新沿用此目录，安装包不包含个人账单。卸载程序不主动删除 Windows 数据目录；手动清理系统数据仍可能删除保险库。

### 默认离线与迁移

- 应用启动不再自动查询汇率；可手动填写，只有点击“联网更新参考汇率”才请求公开数据。桌面界面本身阻止远程网络资源，银行资料链接交由系统浏览器打开。
- 网页版使用 IndexedDB，桌面版使用本机加密文件。两者不会自动同步。
- 网页中解锁旧数据，点击“导出加密备份”，再到桌面版点击“恢复加密备份”，输入备份密码即可迁移。恢复会在确认后替换当前设备的交易、活动和汇率设置；请先备份已有记录。
- `.cardpulse` 备份为 AES-GCM 密文，不是 CSV。忘记密码无法恢复。导出备份包含当前工作区，但不会代替“保存到加密库”。
- 当前没有云同步、遥测或自动更新；升级时下载新版安装包。

## 快速开始

需要 Node.js 和 npm，建议使用 **Node.js 22.20 或更高版本**。浏览器须支持 Web Crypto、Web Worker 和 IndexedDB；请通过本地开发地址或 HTTPS 访问应用。

```bash
git clone https://github.com/leeeway/CardPulse.git
cd CardPulse
npm ci
npm run dev
```

打开终端显示的本地地址，通常为 `http://localhost:5173`。首次使用可点击 **“查看示例数据”**，无需准备真实账单。

## 使用流程

1. **导入账单**：先选择导入银行和卡片，再上传 PDF 或标准 CSV。加密文件会提示输入 PDF 密码；取消则跳过该文件，继续处理其余文件。
2. **检查识别结果**：核对交易和支付渠道，查看每份结单的警告及对账状态。无法确认的记录应与原始 PDF 人工比对。
3. **查看返现估算**：看板汇总本年度截至当天的合资格记录。港币返现按公开参考汇率折算；汇率不可用时，相关人民币合计显示为未知。
4. **保存记录**：点击 **“保存到加密库”**，首次设置主密码，后续使用现有密码保存更新。**导入后不会自动保存。**
5. **恢复或导出**：再次打开应用后解锁本地库；CSV 导出仅包含当前筛选结果。

支持按**记账起止日期**筛选，并可重置全部筛选条件。日期范围包含起止当天，只影响交易列表和 CSV 导出，不改变奖赏计算；起始晚于截止时会提示并禁止导出。此功能自 `v0.2.0-beta.3` 起提供。

### 交易核对与结单管理

交易修正和结单删除自 `v0.2.0-beta.2` 起提供。

- 在交易行点击 **“核对交易”**，修正分类或支付渠道。消费支出可设为消费、费用；入账可设为退款、还款。奖赏立即重新计算，修改前后记录可在核对窗口查看，原始金额、日期和来源保持不变。
- 选择 **“不计奖赏”** 可将该笔记录从内置及自定义活动估算中排除。选择渠道不会自动确认活动登记资格。查阅用 CSV 导出包含当前渠道，但完整修改记录仅保存在加密库和加密备份中。
- 展开 **“查看结单与对账”**，可删除指定结单及其关联交易；其他结单、活动和汇率保留。删除后可重新导入原文件；该文件的人工修正也会随关联交易删除。
- 修正和删除均需点击 **“保存到加密库”** 才持久保存。原文件不受影响；对账结果仍是导入时的金额核验，不代表渠道或活动资格已获银行确认。

`v0.2.0-beta.3` 维护改进：

- 清空数据或成功恢复备份会丢弃未保存的活动编辑草稿；取消或恢复失败会保留当前草稿。仅有手动汇率的工作区也可导出加密备份。

**Pulse 计算说明：** 展开“Pulse 计算明细”可查看人民币／港币基础返现、年度额外奖赏、上下半年消费额度及本年度退款扣回；“Pulse 逐笔说明”显示匹配、排除和待确认渠道。当前模型先合并两半年封顶后的奖赏，再扣本年度匹配退款，不追溯退款原单；未设置汇率时，受影响的人民币折算保持未知。自 `v0.2.0-beta.3` 起提供，内置模型仍需人工核验银行最新条款及资格。

对账状态说明：

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 对账一致 | 已识别的期初、期末结欠与交易净额一致 | 仍需抽查分类和支付渠道 |
| 对账不符 | 计算出的结欠与结单结欠存在差额 | 检查遗漏交易、金额及结欠识别结果 |
| 未验证 | 缺少可识别的期初或期末结欠 | 对照原始 PDF 人工核对 |

对账一致仅表示金额平衡，不代表交易分类、渠道或返现资格已获银行确认。

## 支持范围

| 项目 | 当前支持情况 |
| --- | --- |
| HSBC Pulse | 在受支持结单布局下解析 CNY / HKD 交易，并按内置规则估算返现 |
| HSBC Red | 支持指定 PDF 布局下的卡种与渠道识别；可使用自定义活动估算，不套用 Pulse 费率 |
| 文字型 PDF | 支持英文 `POST DATE` / `TRANS DATE` 表头、英文月份和固定相对列位置；表头上方须能唯一识别币种 |
| 扫描件 / 图片型 PDF | 暂不支持，尚未接入 OCR |
| 加密 PDF | 支持本地输入密码及错误后重试 |
| 导入限制 | PDF 每份最多 25 MB、200 页；标准 CSV 每份最多 5 MB、10,000 笔交易 |
| 文档与界面语言 | 文档提供简体中文、繁体中文和英文；应用支持简体中文／繁体中文即时切换 |

**返现规则是估算模型。** 当前未自动核验银行最新条款、活动登记、商户资格及个人权益条件。具体规则见 [Pulse 配置](src/core/rules/hsbc_pulse.js) 与[核算引擎](src/core/rewards.js)，最终以银行实际入账为准。

文件去重依据 PDF 原始字节内容。改名后的同一文件可识别为重复；内容不同但交易重叠的结单仍需人工排重。旧版保险库没有文件指纹和结单摘要，读取后重新导入时也需检查重复。

解析兼容性已通过合成数据验证，仍需要更多脱敏真实结单样本覆盖不同版式。遇到未支持格式时，请先核查解析结果。

## 多银行、配色与自定义活动

顶部可切换简体中文／繁体中文，以及午夜蓝、明亮白、宝石红、翡翠绿四套配色。语言和配色偏好保存在本地，不包含交易或活动数据。银行卡片用于筛选工作区；导入银行在上传区域独立选择。

### 其他银行如何导入

中银香港、信银国际、恒生、渣打、花旗、星展及其他银行目前支持**标准 CSV**，尚未适配它们的原生 PDF 或各银行专用 CSV 格式。点击“下载 CSV 模板”，将原始明细整理成以下格式；CSV 导入不验证期初、期末结欠。导出的查阅用 CSV 与导入模板格式不同。

```csv
day,transactionDay,description,amount,currency,direction,category,last4,channel
2026-10-01,2026-10-01,EXAMPLE SHOP,100.00,HKD,debit,spend,1234,online
```

必需列为 `day`、`description`、`amount`、`currency`、`direction`。日期使用 `YYYY-MM-DD`；币种为 `HKD` / `CNY`；金额为正数，方向用 `debit` / `credit`。可选分类为 `spend`、`credit`、`repayment`、`fee`；渠道为 `standard`、`applePay`、`unionpayQr`、`online`、`supermarket`、`other`、`baseOnly`、`exclude`。卡号只填写末四位。标准 CSV 在同一银行与卡片内按内容去重，不会合并不同银行的相同明细。任何一行无效时，整个文件拒绝导入并报告行号。

### 配置并计算活动

点击“添加活动”，设置银行、适用卡片或末四位、币种、日期范围、现金回赠比例、支付渠道和商户关键词。选择整个活动、自然月、半年或自然年周期，按需填写每周期消费上限、奖赏上限及净消费门槛。确认条款及登记要求后才计算奖赏；活动新增、编辑和删除均须手动保存到加密库。

- 消费与奖赏上限均按周期生效；留空为不限，填 `0` 表示零额度。
- 门槛使用该周期匹配记录的净消费额。资格条件由用户核对，应用不会从商户名称推断 MCC、地区或银行登记状态。
- 可按记账日期或交易日期计算。选择交易日期时，缺少交易日期的记录不参与。
- 退款在所选日期对应的周期扣回；不释放消费额度，奖赏上限先应用再扣回退款，不回补封顶奖赏。暂不追溯跨周期原单。
- 每个活动只计算一种币种；费率按百分比，最多两位小数。计算过程使用整数定点金额，展示时四舍五入至分。
- 活动独立估算，不自动相加或判断与其他活动、Pulse 基础奖赏的叠加关系。搜索仅影响交易表和导出，不改变活动匹配范围。

**自定义活动计算说明：** 展开“本期估算”，可查看每个周期的消费、退款、净消费、门槛、消费上限、剩余额度、封顶前后奖赏及实际退款扣回。展开“逐笔计算说明”，可查看计入消费／退款或排除的原因，并按计入／排除筛选，每页 25 笔。说明与计算共用筛选逻辑，排除记录展示首个不满足的条件；封顶按周期汇总，不分配为单笔奖赏。未确认渠道会保留提醒，分项显示舍入可能产生尾差。这些说明是临时计算结果，不增加加密库字段，自 `v0.2.0-beta.3` 起提供。

**扩展评估：** 固定费率、封顶、自然周期和门槛适合通用配置，本版已实现。积分／里程兑换、阶梯费率、结单周期、跨期退款追溯、主副卡共享额度及活动叠加需要专门模型；原生银行 PDF 还需要对应版式样本和对账验证。例如[渣打 Smart 官方说明](https://www.sc.com/hk/credit-cards/smart/)采用结单周期口径，不能直接用自然月替代。银行入口链接提供官方资料供人工核验，并非已验证的官方活动模板。

## 隐私与数据

- **账单在本地处理**：应用没有接收账单的业务后端，PDF 解析和返现计算在浏览器内完成。
- **保存时加密**：使用 Web Crypto 的 PBKDF2（SHA-256，100,000 次迭代）派生密钥，再以 AES-256-GCM 加密，网页版密文存放在 IndexedDB，桌面版存放在本机加密文件。主密码不会上传或持久化保存。
- **解锁后可查看明文**：交易在解锁期间存在于应用内存中。手动锁定会清除当前交易及结单状态，下次解锁恢复最后保存的版本。
- **存在公开汇率请求**：仅在用户点击联网更新时，应用才请求 [Frankfurter](https://api.frankfurter.dev/v2/rate/HKD/CNY) 的 HKD/CNY 参考汇率，不发送账单内容，并设置 `credentials: 'omit'` 和 `referrerPolicy: 'no-referrer'`。这不代表整个应用完全不联网。
- **网页版本地库依赖当前浏览器与站点地址**：切换设备、浏览器或访问地址不会自动同步数据。忘记主密码无法找回；清除站点数据也可能删除保险库。
- **CSV 是明文文件**：导出会转义可能触发电子表格公式的单元格，但交易内容仍可直接读取，请妥善保管。

“清空数据”会在确认后删除当前交易、活动及本地保险库。“锁定保险库”遇到未保存修改时会提示是否丢弃，已保存记录保留。

## 开发与贡献

项目使用 React、Vite 和 PDF.js，无业务后端。

```bash
npm test          # Node.js 原生测试套件
npm run build     # 构建静态文件至 dist/
npm run preview   # 在本地预览构建结果

# 可选：安装浏览器并执行端到端回归测试
npx playwright install chromium
npm run test:browser
```

静态资源可部署到支持 HTTPS 的静态托管平台。部署到子路径时需配置 Vite 的 `base`；例如 GitHub 项目站点可使用 `npm run build -- --base=/CardPulse/`。

仓库提供 [GitHub Actions CI 模板](docs/ci.yml)，涵盖 Node.js 22/24 的测试与构建，目前尚未启用。具备相应仓库和工作流权限后，可将模板放入 `.github/workflows/ci.yml`。
