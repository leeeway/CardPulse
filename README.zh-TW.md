# CardPulse

**在瀏覽器中整理信用卡結單，核對交易並估算回贈。**

[简体中文](README.md) · **繁體中文** · [English](README.en.md)

CardPulse 是一個在本機處理資料的信用卡 PDF 結單分析工具。匯入支援的結單後，可以按商戶、幣種和收支篩選交易，檢查結單結欠是否一致，並查看依內建規則計算的回贈估算。需要保留紀錄時，可使用主密碼加密儲存至目前的瀏覽器。

適合希望集中整理多個月份結單，同時讓交易明細留在自己裝置上的使用者。目前主要面向 **HSBC Pulse 雙幣信用卡**；支援範圍見下表。

[快速開始](#快速開始) · [使用流程](#使用流程) · [支援範圍](#支援範圍) · [私隱與資料](#私隱與資料) · [開發與貢獻](#開發與貢獻)

## 能做甚麼

- **整理交易**：批次匯入 PDF，查看交易日期、商戶、幣種、金額及識別到的支付渠道；支援搜尋、篩選和 CSV 匯出。
- **檢查結單**：按幣種核對「上期結欠 + 支出 − 入賬 = 本期結欠」，顯示對賬結果及差額。
- **估算回贈**：依內建 Pulse 規則計算基本及額外獎賞，顯示年度、半年度簽賬額度的使用情況；退款會扣回獎賞，但不釋放已佔用額度。
- **加密儲存**：將交易與結單摘要加密儲存於目前的瀏覽器，重新整理後輸入主密碼還原；亦可手動鎖定或清除。
- **減少誤操作**：按 PDF 檔案內容識別重複匯入，提示解析異常及尚未儲存的修改。

## 快速開始

需要 Node.js 和 npm，建議使用 **Node.js 22.13 或更新版本**。瀏覽器須支援 Web Crypto、Web Worker 和 IndexedDB；請透過本機開發網址或 HTTPS 存取應用程式。

```bash
git clone https://github.com/leeeway/CardPulse.git
cd CardPulse
npm ci
npm run dev
```

開啟終端機顯示的本機網址，通常為 `http://localhost:5173`。首次使用可點擊 **「查看示例数据」**，毋須準備真實結單。

## 使用流程

1. **匯入結單**：點擊上載區域或拖入一個或多個 PDF。加密檔案會提示輸入 PDF 密碼；取消則跳過該檔案，繼續處理其餘檔案。
2. **檢查識別結果**：核對交易和支付渠道，查看每份結單的警告及對賬狀態。無法確認的紀錄應與原始 PDF 人工比對。
3. **查看回贈估算**：儀表板彙總本年度截至當天的合資格紀錄。港幣回贈按公開參考匯率折算；匯率無法取得時，相關人民幣合計顯示為未知。
4. **儲存紀錄**：點擊 **「保存到加密库」**，首次設定主密碼，之後使用現有密碼儲存更新。**匯入後不會自動儲存。**
5. **還原或匯出**：再次開啟應用程式後解鎖本機資料庫；CSV 匯出只包含目前篩選結果。

對賬狀態說明：

| 狀態 | 含義 | 建議操作 |
| --- | --- | --- |
| 對賬一致 | 已識別的期初、期末結欠與交易淨額一致 | 仍需抽查分類和支付渠道 |
| 對賬不符 | 計算出的結欠與結單結欠存在差額 | 檢查遺漏交易、金額及結欠識別結果 |
| 未驗證 | 缺少可識別的期初或期末結欠 | 對照原始 PDF 人工核對 |

對賬一致只表示金額平衡，不代表交易分類、渠道或回贈資格已獲銀行確認。

## 支援範圍

| 項目 | 目前支援情況 |
| --- | --- |
| HSBC Pulse | 在支援的結單版面下解析 CNY / HKD 交易，並依內建規則估算回贈 |
| HSBC Red | 支援卡種與渠道識別、交易查閱和匯出；尚未接入回贈計算，不計入 Pulse 儀表板 |
| 文字型 PDF | 支援英文 `POST DATE` / `TRANS DATE` 表頭、英文月份和固定相對欄位位置；表頭上方須能唯一識別幣種 |
| 掃描件 / 圖像型 PDF | 暫不支援，尚未接入 OCR |
| 加密 PDF | 支援在本機輸入密碼及錯誤後重試 |
| 匯入限制 | 每個檔案最多 25 MB、200 頁 |
| 文件與介面語言 | 文件提供簡體中文、繁體中文和英文；目前應用程式介面以簡體中文為主 |

**回贈規則是估算模型。** 目前未自動核驗銀行最新條款、活動登記、商戶資格及個人權益條件。具體規則見 [Pulse 設定](src/core/rules/hsbc_pulse.js) 與[計算引擎](src/core/rewards.js)，最終以銀行實際入賬為準。

檔案去重依據 PDF 原始位元組內容。重新命名的同一檔案可識別為重複；內容不同但交易重疊的結單仍需人工排重。舊版保險庫沒有檔案指紋和結單摘要，讀取後重新匯入時亦需檢查重複。

解析相容性已透過合成資料驗證，仍需要更多脫敏真實結單樣本涵蓋不同版面。遇到未支援格式時，請先核查解析結果。

## 私隱與資料

- **結單在本機處理**：應用程式沒有接收結單的業務後端，PDF 解析和回贈計算均在瀏覽器內完成。
- **儲存時加密**：使用 Web Crypto 的 PBKDF2（SHA-256，100,000 次迭代）衍生金鑰，再以 AES-256-GCM 加密，密文存放於 IndexedDB。主密碼不會上載或持久儲存。
- **解鎖後可查看明文**：交易在解鎖期間存在於應用程式記憶體中。手動鎖定會清除目前交易及結單狀態，下次解鎖還原最後儲存的版本。
- **存在公開匯率請求**：應用程式會請求 [Frankfurter](https://api.frankfurter.dev/v2/rate/HKD/CNY) 的 HKD/CNY 參考匯率，不傳送結單內容，並設定 `credentials: 'omit'` 和 `referrerPolicy: 'no-referrer'`。這不代表整個應用程式完全不連線。
- **本機資料庫依賴目前瀏覽器與網站網址**：切換裝置、瀏覽器或存取網址不會自動同步資料。忘記主密碼無法找回；清除網站資料亦可能刪除保險庫。
- **CSV 是明文檔案**：匯出會轉義可能觸發試算表公式的儲存格，但交易內容仍可直接讀取，請妥善保管。

「清空数据」會在確認後刪除目前交易及本機保險庫。「锁定保险库」遇到尚未儲存的修改時會提示是否捨棄，已儲存紀錄保留。

## 開發與貢獻

專案使用 React、Vite 和 PDF.js，無業務後端。

```bash
npm test          # Node.js 原生測試套件
npm run build     # 建置靜態檔案至 dist/
npm run preview   # 在本機預覽建置結果
```

靜態資源可部署至支援 HTTPS 的靜態託管平台。部署至子路徑時需設定 Vite 的 `base`；例如 GitHub 專案網站可使用 `npm run build -- --base=/CardPulse/`。

儲存庫提供 [GitHub Actions CI 範本](docs/ci.yml)，涵蓋 Node.js 22/24 的測試與建置，目前尚未啟用。具備相應儲存庫和工作流程權限後，可將範本放入 `.github/workflows/ci.yml`。

主要模組：

| 路徑 | 職責 |
| --- | --- |
| [`src/App.jsx`](src/App.jsx) | 匯入、篩選、儀表板與保險庫互動 |
| [`src/core/pdf.js`](src/core/pdf.js)、[`statement.js`](src/core/statement.js) | PDF 文字擷取、座標解析與結單摘要 |
| [`src/core/reconciliation.js`](src/core/reconciliation.js) | 金額轉換與結欠校驗 |
| [`src/core/rewards.js`](src/core/rewards.js)、[`rules/`](src/core/rules/) | 回贈估算及卡種規則 |
| [`src/core/crypto.js`](src/core/crypto.js)、[`storage.js`](src/core/storage.js) | 加密與 IndexedDB 持久化 |
| [`tests/`](tests/) | 解析、精度、回贈、儲存及匯出回歸測試 |

歡迎透過 [Issues](https://github.com/leeeway/CardPulse/issues) 回報問題或提交改進。解析問題請提供銀行與卡種、預期結果和已脫敏的版面範例；請勿公開真實卡號、姓名、交易明細或 PDF 密碼。

修改功能、支援範圍或使用流程時，請同步更新三個語言版本，保持章節順序和功能狀態一致。新增卡種或解析規則時，請附上脫敏或合成回歸案例。
